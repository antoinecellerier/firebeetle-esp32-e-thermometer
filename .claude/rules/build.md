# Build configuration rules

Full rationale: `docs/build-system.md`. These are the ones that destroy data or
silently mis-build.

## Partition table

- Lives in `partitions.csv` (2048KB single app, no OTA; 1920KB `history` data
  partition) and is referenced from **BOTH** `board_build.partitions`
  (PlatformIO ignores the sdkconfig partition selection and always generates from
  this option) and `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME` (idf.py). Keep them
  pointing at the same file.
- **`history` is at offset 0x10000 and must stay there.** It comes before
  `factory` so a future resize grows it upward and leaves written archive content
  in place; moving its start orphans years of data.
- Changing the table relocates the app, so that one upload must not be
  interrupted.

## Board macros

`ARDUINO_DFROBOT_FIREBEETLE_2_ESP32E` / `ARDUINO_XIAO_ESP32C6` (legacy names,
kept) derive from `IDF_TARGET` in `src/CMakeLists.txt`, **not** platformio.ini.
`THERMOMETER_C6_BOARD` selects the custom rev A PCB.

## platformio.ini

**Base sections must be plain sections, not `[env:...]`.** An `[env:...]` mixin
is itself a buildable, half-configured target, and `extends` only inherits
reliably from plain sections — `build_flags` in particular does not inherit the
way you would expect.

## sdkconfig

Authored `sdkconfig.defaults` and `sdkconfig.defaults.<target>` are tracked;
generated `sdkconfig.<env>` files are gitignored. CPU is fixed at 80MHz at build
time. libc is pinned to newlib (`CONFIG_LIBC_NEWLIB`) because PlatformIO's
`ulp.py` doesn't forward `ADD_PICOLIBC_SPECS` to the LP-core sub-build.

Reading a *generated* `sdkconfig.<env>` tells you what the build actually used;
reading the authored defaults tells you what was chosen on purpose. Don't quote
a generated value as a project decision — several are IDF defaults that follow
from another selection.

## Components and generated sources

- Only the panels selectable in `local-secrets.h` are compiled. **Add the panel
  `.cpp` to `components/gxepd2/CMakeLists.txt` when enabling a new `USE_*`
  panel** — otherwise the link fails on a missing vtable that names nothing
  useful.
- **Never name a project header like an IDF-internal one.** IDF's mbedtls exposes
  a private `common.h` that shadowed ours — hence `app_common.h`.
- **Don't modify `include/generated/`** — auto-generated by the font scripts and
  gitignored.
- Builds run with `-Werror`, so `#warning` fails the build. Use
  `#pragma message` for build-time notices.
