# Editing the board

All commands run from `hardware/thermometer-c6/`.

The harvest loop itself — GUI copy, `extract_tracks.py`, `hand_diff.py`, the
gate, the commit — is **`HAND-ROUTING.md`**. Don't reimplement it from memory;
one thing from it is worth repeating because it is destructive:

> Harvest with `extract_tracks.py … -o generator/pcb_routes.py`. **Never a shell
> `>` redirect** — it truncates `pcb_routes.py` before the harvester's own
> imports run, and `pcb_routes.py` is the board's copper.

## What DRC actually enforces

**Read `thermometer-c6.kicad_dru`** — it is short, generated by
`generator/pcb.py` (so never hand-edited), and it is the only honest answer.
Netclass clearance and widths come from the `.kicad_pro` netclasses on top of it;
the board minimum is overridden by the Default netclass, so the number in the
board setup is not what you get.

Two things the DRU does not tell you:

- **Centre-to-centre is what you actually place against.** Two tracks need
  `clearance + w1/2 + w2/2` between centrelines; a via needs
  `clearance + via_dia/2 + w/2` from a track centre, and `drill/2 + 0.4` from
  any other hole. Derive from the current DRU values rather than reusing a
  number from a previous session.
- **Via-in-pad is fine for JLC** and has solved several otherwise-impossible
  escapes.

`make hand` copies the `.kicad_dru` into the GUI working copy. Without it the
GUI and any `kicad-cli pcb drc` run from that directory silently drop every
scoped rule and report violations the real board does not have (68 vs 7,
observed).

## Geometry traps

These are why a clearance check reads wrong, in both directions.

- **`pad.GetSize()` is pre-rotation.** Derive every margin from
  `pad.GetBoundingBox()` — which is what `verify/pads.py` prints.
- **Clearance to a pad corner is the distance to the track *segment*,** not to
  its infinite line. Getting this wrong reads as a violation that isn't there,
  and hides ones that are.
- **Two parallel 45° lanes 0.5mm apart in y are only 0.354mm apart
  perpendicular.** A fan-out cannot turn all its lanes at once: cascade the
  drops, one x-window each, so no lane is ever diagonal beside a diagonal.
- **A bench pad on an HV net is a copper wall on its layer** — the pad plus HV
  clearance on each side. Check whether the testpoint sits inside the
  `fpc-fanout` area before assuming it gets the relaxed clearance; the ones
  outside it don't, and one of them pinches the B.Cu channel south of the
  booster to a narrow slot.
- **A through-hole via inside an SMD pad still has an F.Cu annulus,** so it must
  clear F.Cu copper crossing that pad's face, not just B.Cu.

## Two ways the render lies

- **pcbnew's zone fill is not byte-stable.** Back-to-back `pcb.py` runs can leave
  `thermometer-c6.kicad_pcb` dirty with nothing but `(xy …)` fill coordinates
  changed. `git diff` it before believing you changed the board. (`make fab`
  defends against this with a `git checkout --` of the board before its
  tree-clean guard.)
- **Stale `__pycache__` renders phantom copper.** Rewriting a generator module
  twice within the same second at the same file size makes the old bytecode
  cache entry look valid, and the next `pcb.py` renders copper that is not on
  disk — phantom DRC shorts, gate flapping. Any tool that rewrites generator
  modules in a loop must run children with `PYTHONDONTWRITEBYTECODE=1`
  (`straighten.py` does). **When DRC results look impossible,
  `rm -rf generator/__pycache__` and re-render before believing them.**

Also: the DRC JSON written under `out/` goes stale. Regenerate before reading it.

## Scripting the board (pcbnew, KiCad 10)

Prefer the `verify/` tools below; write ad-hoc pcbnew only for one-off geometry —
and start from the shared helper (board origin is (100,100); pcbnew coords are
nm):

```python
import sys; sys.path.insert(0, "verify")
from geom import load, rel, vi, seg_width
b = load()                       # committed board; load("out/hand/...", fill=False)
x, y = rel(pad.GetPosition())    # nm -> board-mm, origin removed
```

- **Track vs via width differ**: `track.GetWidth()` takes no argument;
  `via.GetWidth(pcbnew.F_Cu)` does. Calling `GetWidth()` on a via spams
  `PCB_VIA::GetWidth called without a layer` to stderr — harmless, drop with
  `2>/dev/null`.
- Element type: `t.Type() == pcbnew.PCB_VIA_T` / `PCB_TRACE_T` / `PCB_ARC_T`.
- To import a `verify/` or `generator/` module, `sys.path.insert(0, "verify")`
  then `import gnd_islands`; run with `PYTHONDONTWRITEBYTECODE=1`.

`generator/pcb.py` env interface: `PCB_NO_ROUTES=1` (authored copper only),
`PCB_OUT_DIR=<dir>` (render target), `FAB_STAMP="<hash> <date>"` (silk stamp).

Toolchain present: `kicad-cli` 10.0.4, the `pcbnew` python module, `inkscape`,
`convert`/`magick`, `freecad`/`freecadcmd` (lowercase), `pdftoppm`, `gs`.
Absent: `rsvg-convert`, `openscad`, `zip` (use `python3 -m zipfile`).

## Review tools (`verify/`)

Usage is in each module's top docstring — **they do not parse `--help`.**

| Tool | Answers |
|---|---|
| `net.py NET [NET …]` | one net at a glance: authored TRACKS/VIAS with `pcb_layout.py` line numbers and island grouping, routed copper, pads, stragglers |
| `pads.py [REF \| REF.PAD \| net:N \| box:…]` | pad/courtyard geometry (bounding boxes, so rotation-correct) |
| `who.py NET W x,y [radius]` | nearby copper with distances and margins — names the culprit a bitmap can't |
| `plot_pcb.py [--crop …]` | board map, courtyards, ratsnest |
| `copper_stats.py [BOARD] [--vs REF]` | routed-copper census; `--vs` takes a board file or git rev and prints the A/B delta |
| `gnd_islands.py [BOARD] [--png OUT]` | GND connectivity + single-point-of-failure audit; pass `out/hand/…` to audit a GUI copy |
| `freespot.py W H [--ignore=…] [--near=…]` | courtyard-aware free rectangles — has a starved part anywhere else to go? |
| `occupancy.py` / `reach.py` / `probe.py` / `gap.py` | corridor and reachability analysis; built for the retired A* and documented in `ROUTER-NOTES.md`, still useful for "why can't this net get there" |

Reason about corridors from `occupancy.py`, never from intuition or from the
board renders.

## Reviewing visual changes

After a silk or placement change: `make pdf`, then crop each zone with
`pdftoppm -r 200 -png -x/-y/-W/-H` (px = mm × 200/25.4; origins and sizes are in
`layout.ZONES`), Read the PNGs, and iterate until clean. A render you have not
looked at is not a review.
